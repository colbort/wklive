# Option 整改实施与验收计划

## 1. 使用方式

本文是 `services/option` 的实施台账。设计依据见
[`option-design-review.md`](option-design-review.md)，运行与应急流程见
[`option-operations-runbook.md`](option-operations-runbook.md)。

状态定义：

- `TODO`：尚未实施。
- `DOING`：正在实施，不能作为已完成能力。
- `VERIFYING`：代码完成，等待完整验收证据。
- `DONE`：实现、迁移、测试、文档和验收证据全部完成。
- `EXTERNAL`：需要外部平台或业务决策；仓库内可准备内容已完成。
- `DEFERRED`：不属于当前产品范围且无可调用入口；满足表内进入条件后重新立项，不作为当前上线阻断。

任何项目只有在“验收标准”全部满足并记录证据后才允许改为 `DONE`。

## 2. 发布原则

1. P0 全部完成前，Option 只能用于模拟盘和开发联调。
2. 任何卖方产品上线前，P0、卖方相关 P1 和生产运行门禁必须完成。
3. 组合保证金、美式行权、实物交割分别独立验收，不因欧式现金通过而自动开放。
4. 功能开关默认关闭；没有明确完成证据的能力不能由运营配置绕过。
5. 迁移必须可重复执行，历史数据必须有校验和回滚/前滚方案。

## 3. P0 资金与清算正确性

### OPT-P0-001 统一风险账户与 Asset 钱包范围

- 状态：`VERIFYING`
- 问题：Option 按 `account_id` 计算风险，Asset 按用户钱包保存余额，同一余额可能被多个风险账户重复使用。
- 目标设计：Option 风险权益按 `(tenant_id, user_id, settle_coin)` 用户钱包级聚合；业务订单和持仓仍可保留 `account_id` 作为策略/展示维度，但不能形成独立资金池。
- 修改范围：
  - 风险账户使用固定资金池账户标识，不再按业务 `account_id` 重复读取余额。
  - 组合保证金准入聚合该用户全部 Option 账户的持仓、活动订单和保证金批次。
  - 下单检查用户钱包级风险状态。
  - 自成交保护至少按 `user_id` 生效，不能用不同 `account_id` 绕过。
  - 管理端/API 明确 `account_id` 不代表独立资金子账户。
- 验收标准：
  - 同一用户两个 `account_id`、同一币种只产生一个风险权益总额。
  - 两账户卖方头寸的维持保证金均计入同一风险账户。
  - 任一账户触发用户钱包风险限制后，两账户均不能增加风险。
  - 组合保证金订单准入不能通过拆分 `account_id` 获得额外抵扣或重复余额。
  - 跨账户同用户订单不能成交。
  - 单元测试、MySQL 集成测试和 Asset RPC 端到端测试通过。

### OPT-P0-002 修正净清算权益公式

- 状态：`VERIFYING`
- 问题：当前使用 `Asset total + unrealized PnL`，权利金已经进入 Asset 后会被重复计算。
- 目标公式：

```text
equity = Asset total
       + long option mark value
       - short option mark value
       + confirmed pending adjustments
```

- 修改范围：
  - 风险扫描独立累计期权净市值。
  - `unrealized_pnl` 继续作为展示指标，不参与重复计价。
  - 风险账户增加或复用可审计字段记录净期权市值。
  - 补充多头、空头、价差、部分平仓、费用、行权和到期恒等式测试。
- 验收标准：
  - 多头支付权利金后，在标记价不变时净清算权益不变（忽略手续费）。
  - 空头收到权利金后，在标记价不变时净清算权益不变（忽略手续费）。
  - 标记价变化一单位时，权益按净 Delta 数量的线性持仓市值变化。
  - 多空同数量同合约完全对冲时，净期权市值为 0。
  - 风险率和强平触发使用新权益。

### OPT-P0-003 拆分行情来源与新鲜度

- 状态：`VERIFYING`
- 问题：标的价、标记价和 Greeks 共用 `snapshot_time`，标的更新会掩盖标记价陈旧。
- 修改范围：
  - `t_option_market` 增加 `underlying_snapshot_time`、`mark_snapshot_time`、`greeks_snapshot_time`。
  - 保留旧 `snapshot_time` 作为兼容字段，迁移期只表示整条记录最后可用时间，不再用于风险判定。
  - 标的消费者只更新标的时间；成交/定价引擎只更新标记价时间；Greeks 单独更新。
  - 下单、组合保证金、风险扫描、主动行权分别检查所需输入时间。
- 验收标准：
  - 仅刷新标的价不能让陈旧标记价通过风险检查。
  - 仅刷新标记价不能让陈旧标的价通过行权或保证金检查。
  - 数据迁移后未能证明时间来源的旧记录默认不可用于卖方新开仓。
  - 新旧 API 兼容，管理端可看到各时间戳和过期状态。
- 当前结果：
  - 交易态合约已按租户输出标的/标记价缺失、超过30秒或未来时间的异常合约数和最早时间，
    并落地 OPT-A001/A002 规则；健康租户隔离 MySQL 断言通过。
  - Greeks 已检测缺失和未来时间并落地基础规则；“超过产品阈值”仍缺合约级批准参数，
    不擅自复用30秒阈值，因此 OPT-A003 仅部分完成。

### OPT-P0-004 修复保证金释放币种

- 状态：`VERIFYING`
- 问题：到期、强平和管理强撤部分路径使用 `fee_coin`，实物 Call 实际冻结 `margin_coin/underlying_coin`。
- 修改范围：所有释放、消耗和对账路径统一使用 `OptionOrderMarginCoin`。
- 验收标准：
  - 实物 Call/Put 在用户撤单、IOC/FOK 撤余、到期、管理强撤、强平撤单时均使用正确币种。
  - 重放释放指令不会重复释放。
  - 不存在剩余直接用 `FeeCoin` 处理 `MarginAmount` 的代码路径。

### OPT-P0-005 正式到期结算价

- 状态：`VERIFYING`
- 问题：当前使用任务运行时最新单点行情，没有绑定合约到期窗口。
- 目标设计：
  - 合约配置结算源、窗口起止偏移、算法、最小样本数和价格精度。
  - 只从不可变市场快照计算，样本时间必须位于正式窗口。
  - 支持 TWAP/中位数等确定性算法、异常值过滤、版本化复核和发布。
  - 结算任务迟到也必须重放到期窗口，不能使用到期后任意价格。
- 验收标准：
  - 到期前、窗口内、到期后样本混合时只使用窗口内样本。
  - 样本不足保持等待并告警，不以 0 或任务当前价结算。
  - 相同样本可确定性重算同一结果。
  - 人工更正产生新版本和完整审批审计，旧版本不可覆盖。
  - 结算开始后使用已发布版本，不受实时行情变化影响。
- 当前监控结果：
  - 已按租户输出“到期60秒仍无已确认价格”和“已确认价格的来源、算法、窗口、样本数或
    证据集合不符合合约规则”两类水位，并分别绑定 OPT-A010/OPT-A011 规则和查询索引。
  - 隔离库精确计数及健康租户无非0泄漏纳入 OPS-010；生产通知与完整窗口/更正/结算 E2E
    仍是上线证据。

### OPT-P0-006 美式行权指派正确性

- 状态：`VERIFYING`
- 问题：只读取 500 个空头、全合约取消平仓单，且当前顺序为 `id DESC`。
- 目标设计：采用明确的可审计 FIFO 指派，以空头持仓首次建立时间和持仓 ID 升序；分页/原子锁定直到满足数量，只处理实际被指派账户。
- 验收标准：
  - 1、500、501、5000 个空头场景均能完成指派。
  - 指派顺序可重复计算且符合已发布规则。
  - 未被指派空头的平仓单不受影响。
  - 并发行权、平仓和任务重放不超分配、不重复扣款。
  - 指派数量总和等于行权数量，资金总扣减等于多头收入加费用。

## 4. P1 交易、风险与产品完整性

### OPT-P1-001 风险任务故障隔离

- 状态：`VERIFYING`
- 目标：按租户、合约和风险账户隔离失败，保存扫描水位；坏行情账户进入保守限制并告警，不中断其他账户。
- 验收标准：构造一个坏行情账户后，其他租户和账户仍在一个任务周期内刷新；坏账户禁止增加风险。
- 当前结果：
  - 每次实际扫描按租户记录钱包组总数、失败数、失败比例和完成时间；收集/重置阶段失败另用
    有限 stage Counter，失败账户比例超过5%升 critical。指标不从存量 `RESTRICTED` 状态反推。
  - 旧租户在下一次无活动组时显式清零，防止标签消失被误判恢复；指标注册、比例和清零单测通过。
- 待验证：跨租户坏行情/Asset 故障注入、调度中断、生产抓取与通知升级链路。

### OPT-P1-002 交易完整性控制

- 状态：`VERIFYING`
- 范围：用户持仓限额、净空限额、OI 限额、价格带、熔断/停牌、用户 kill switch、全用户 STP、错单处理。
- 验收标准：每项控制具有配置、原子准入、拒绝原因、指标、审计和并发测试。
- 当前结果：
  - 合约已增加用户多头上限、用户空头上限、合约 OI 上限、订单价格带和标记价跳变熔断阈值；交易态不允许五项配置为 0。
  - 下单在用户控制行和合约行锁内执行准入。投影敞口包含已持仓、活动开仓委托及成交后尚未落仓的 outbox 增量，避免异步窗口和并发请求绕过限额。
  - 标记价必须为 30 秒内的正数；价格带边界为闭区间。标记价跳变达到阈值时，合约原子切到 `PAUSED`，随后幂等撤销活动订单。
  - 用户可启用 kill switch；启用后立即阻止新单并撤销该用户全部活动订单。只有管理员可带理由解除，启用、解除和拒单均留不可变审计。
  - STP 已按 `user_id` 跨账户生效，固定采用 cancel-taker；不会为了绕过自成交而继续匹配更差的外部价格。
  - 后台已可查看用户控制状态和控制事件，并执行 kill switch 解除；配置修改、状态修改、熔断和 STP 也进入控制事件表。
  - 异常成交已采用“保留原成交 + 追加现金更正”流程：创建案件即原子暂停合约并撤销活动订单；
    更正仅允许原成交双方、费用或保险账户，以原成交币种提交精确平衡的借贷分录；另一管理员
    复核后先执行全部扣款再执行入账，失败进入可重试/人工处理，案件和分录由数据库保证不可篡改。
    不支持删除原成交或通过反向下单伪造撤销。
  - 已增加低基数租户指标和告警规则：交易态缺配置/近5分钟拒单、单合约1分钟价格带拒单
    超20笔、熔断事件、暂停30秒残单、kill switch 30秒残单、STP 用户/租户窗口、用户合约
    限额拒单窗口、kill switch 关联资金释放失败，以及超龄/人工异常成交更正。业务身份仍从
    不可变事件和工作台下钻。
  - `20260731_zr_option_operations_monitoring_indexes.sql` 提供既有跨租户时间窗口索引且保持
    已记录校验和不变；kill switch 资金释放失败的增量索引由
    `20260731_zs_option_time_sensitive_monitoring_indexes.sql` 提供。
- 待验证/接入：
  - 限额并发 20 单、启用 kill switch 与成交竞争、熔断批量撤单、跨账户 STP 的 MySQL/消息/Asset E2E 尚未执行。
  - 异常成交案件创建/并发复核、Asset 成功响应丢失、扣款不足、人工重试、最终资金守恒和用户通知 E2E 尚未执行。
  - 仓库级指标和规则已实现；价格带“超过请求10%”仍缺全请求分母，生产 Prometheus/
    Alertmanager 部署、连续恢复、通知路由和案件联动仍归 P1-008。
  - 做市商专属集中度限额和 MMP 不在本项内，分别归 P1-004/P1-003。

### OPT-P1-003 MMP

- 状态：`VERIFYING`
- 目标：实现做市商报价组、成交数量/损失阈值、滚动窗口、自动撤单、冷静期和人工恢复；完成前 API 不得宣称支持。
- 验收标准：阈值触发后同组全部 MMP 报价原子进入取消流程，非 MMP 用户单不受影响，冷静期内拒绝新 MMP 报价。
- 当前结果：
  - 以 `(tenant_id,user_id,contract_id,group_code)` 隔离配置和实时窗口；MMP 单必须为
    `POST_ONLY`，且 `mmp` 与 `mmp_group` 成对、订单创建后不可改。
  - 下单在合约、用户控制和 MMP 配置行锁内准入。未配置、禁用、已触发或冷静期中的
    报价分别明确拒绝，不会降级成普通订单。
  - 只统计 maker 成交量和笔数。不利损失按成交前新鲜标记价计算：
    maker 买为 `max(成交价-标记价,0)*数量*乘数+maker 手续费`；
    maker 卖为 `max(标记价-成交价,0)*数量*乘数+maker 手续费`。
  - 数量、笔数或损失任一达到阈值即原子转 `TRIGGERED`；当前 maker 剩余量在成交事务内
    撤销，提交后幂等撤销同组其他活动报价，非 MMP 和其他组不受影响。
  - 冷静期结束后的首笔新 MMP 报价可原子清空窗口并恢复；管理员也可带复核原因人工恢复。
    配置变更和人工恢复均先阻断新报价、撤销残单，成功后才激活。
  - REST、RPC、SDK、管理端配置/实时状态/错误/人工恢复工作台和不可变控制事件已接入。
  - 租户级 `mmp_exception` 水位已覆盖触发10秒后同组残单、撤单错误和启用配置异常停留
    `DISABLED` 超60秒，并配套 `OptionMMPException` 规则和监控索引。
- 待验证：
  - 触发成交与并发下单/配置变更、100+ 组内订单批量撤销、撤单中 Asset 响应丢失、
    冷静期边界和消息通知的预生产 E2E 尚未执行。
  - 生产指标抓取、通知路由和告警恢复演练归 P1-008；未完成 E2E 和审批前不得宣称生产可用。

### OPT-P1-004 组合保证金模型治理

- 状态：`VERIFYING`
- 范围：历史回测、极端压力、参数版本、集中度/流动性附加、模型审批和独立验证。
- 已确认设计边界：
  - 继续使用受限的 `EXPIRY_SCENARIO_V1`，只允许同租户、同结算币、同标的、
    同到期日内抵扣；不提供跨到期日、跨标的、波动率相关性或美式期权抵扣。
  - 风险参数按“租户 + 结算币”形成不可覆盖的递增版本；参数内容创建后不可修改，
    只能由另一管理员批准或拒绝，批准时记录生效时间、审批意见和验证证据引用。
  - 新版本生效时关闭被替代版本的有效期；回滚必须复制历史参数创建更高版本并重新审批，
    不允许直接篡改或重新激活历史版本。
  - 初始/维持价格冲击至少取“已审批模型参数”和“合约参数”中的较大值，
    防止模型配置弱化单合约底线；情景仍包含零价格、现价、各执行价、二倍现价，
    并增加配置化价格冲击集合。
  - 在情景最大损失与裸空头底线之外，按同到期组合的净空头风险名义金额计算
    集中度附加和流动性附加；附加项只能增加、不能减少保证金。
  - 下单与定时风险扫描必须解析同一个当前有效版本。没有已批准且处于有效期的版本时，
    新增组合风险的卖单拒绝，存量组合风险账户转 `RESTRICTED`，不得静默回退到旧算法。
  - 风险账户快照保存模型配置 ID/版本、情景损失、裸空头底线、集中度附加和流动性附加，
    使告警、强平复核和历史报告可以还原计算依据。
  - 运营采样按同一 `FindActive` 排序口径定位当前版本：存在组合持仓但无有效参数输出
    `portfolio_risk_config_missing`；风险账户两个扫描周期后仍保存旧 ID/版本输出
    `portfolio_risk_version_mismatch`，后者按 SEV-1 路由。
- 仓库内验收标准：
  - 数据库约束和服务逻辑共同保证版本唯一、参数不可覆盖、四眼审批、有效期和回滚留痕。
  - 单元测试覆盖零价格、五倍价格、冲击边界、跨期限不抵扣、集中度阈值、
    流动性附加单调性、缺配置拒绝以及审批人不能等于创建人。
  - 管理端能够创建、审批/拒绝、查询版本，风险账户能够显示实际使用的版本和附加项。
  - 迁移脚本可重复执行，并验证不能直接修改已审批参数。
- 上线外部证据（仓库不能自行伪造）：
  - 使用生产代表性历史行情和持仓样本完成回测；数据集范围、缺失值处理、阈值依据、
    例外组合和结果摘要归档到版本的 `evidence_ref`。
  - 风控以外人员完成独立模型验证并签字；至少验证理论合理性、实现一致性、
    压力覆盖、限制条件和模型风险。

### 5.5 OPT-P2-007 组合/价差单原子执行

- 状态：`VERIFYING`
- 标准要求与首版边界：
  - 组合单必须作为一个订单提交，腿比例化到最简整数，成交必须保持比例和净价约束；
    禁止把多个单腿 API 顺序调用包装成“原子组合”。
  - 首版建立独立 Complex Order Book，只允许2～4条不同的期权腿、比例1～8、至少一买一卖；
    所有腿必须同租户、同用户/账户、同标的、同到期、同结算/报价币、同合约单位和乘数，
    且为现金结算、开仓、非 MMP。比例最大公约数必须为1。
  - 首版支持 `LIMIT` 休眠和 `FOK`，按父单数量乘各腿比例成交；不支持 MARKET、IOC、
    POST_ONLY、平仓腿、股票腿、跨到期/跨标的、策略拍卖或与单腿簿隐含 legging。
  - 净价定义为每份组合的 `Σ(买腿价格×比例) - Σ(卖腿价格×比例)`；
    正数为净支出、负数为净收入。每条腿价格必须满足自身 tick，组合净价必须与腿价精确相等。
  - 为避免把尚未验证的组合抵扣变成资金缺口，首版只接受逐仓卖方保证金，双方按各腿权利金、
    最大 maker/taker 费率及卖方保证金毛额预冻结，不使用跨腿组合保证金抵扣。成交同时满足
    父单净价与 taker 每腿限价：买腿不得高于其腿限价，卖腿不得低于其腿限价。
  - 首版一次准入最多与价格时间优先的一个反向父单成交。`LIMIT` 成交后余量重新休眠；
    `FOK` 要求该一个最优 maker 足量，否则0腿成交并全腿释放。跨多个 maker 聚合 FOK
    和自动连续扫簿属于后续能力。
- 原子性设计：
  - 父单、不可变腿、影子子单、资金指令和客户端幂等键同事务创建。影子子单不得进入单腿盘口、
    不得被单腿 matcher、改单、单腿撤单或公开深度消费。
  - 所有必需冻结成功后父单才进入策略簿。候选父单必须具有完全相反的规范化策略键；
    价格优先、时间优先，同用户跨账户 STP。
  - 匹配事务按父单 ID、稳定腿/影子单、用户键和合约 ID 的规范顺序锁定，重新检查交易状态、
    日历/halt、行情新鲜度、价格带、kill switch、腿限价和资金状态；用户/OI限额已在影子单
    创建时按全量腿占用，撮合前不得释放该投影敞口；随后一次性写入全部腿成交、撮合序号、
    margin lot、资产指令和 outbox。任一腿失败则整个数据库事务0腿成交。
  - 每次组合成交保存统一 `combo_match_no` 和稳定 `combo_leg_no`。资产仍通过现有幂等指令
    异步执行；同一组合成交组全部买方扣冻结成功前，任何腿的持仓事件均不可运行。之后各合约
    按原撮合序号幂等落仓，短暂水位差异由 outbox/OI 告警监控，不伪称跨合约持仓写入是一个事务。
    父单完成/撤销只按原腿冻结业务号释放未使用余额。

    腿比例要求约分到最低项。首版策略簿与该核心语义一致。

### 5.6 OPT-P2-008 RFQ、大宗与做市义务
