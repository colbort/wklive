# Option 生产验收测试计划

## 1. 目标与退出条件

本计划验证资金守恒、风险准入、交易完整性、行权、到期结算、故障恢复和运营可执行性。生产退出条件：

1. 适用 P0 全部为 `DONE`；卖方、美式、实物、组合保证金各自依赖的 P1 全部为 `DONE`。
2. 自动化单测、`go test -race`、`go vet`、迁移重复执行和 API/UI 类型检查通过。
3. 下表所有适用场景通过，无开放 SEV-1/2 缺陷。
4. Option 账、Asset 流水和余额差额为 0。
5. 技术、风控、清算和运营签字；生产参数另按上市检查表签字。

## 2. 环境与证据

- 独立预生产租户，时间可控的合约和权威行情快照源。
- MySQL、Redis、消息队列、Option、Asset、Market 使用生产同版本配置。
- 测试用户至少覆盖两个 `account_id`、多/空双方、费用/保险/兜底账户。
- 每个用例保存：输入参数、数据库前后快照、RPC 响应、消息、日志、Asset 流水、余额、告警和清理结果。
- 金额断言使用 DECIMAL 精确比较，不以浮点误差忽略非零差额。

## 4. 会计恒等式

每笔交易/行权/结算至少验证：

```text
买方权利金扣款 = 卖方权利金入账 + 交易手续费
空方行权/结算扣款 = 多方净入账 + 行权手续费
保证金初始冻结 = 已消耗 + 已释放 + 当前剩余 + 当前待处理
用户总收益 = 权利金交易盈亏 + 行权/结算盈亏 - 各类费用
```

系统级验证：

```text
所有用户 Asset 净变化
+ 费用账户净变化
+ 保险账户净变化
+ 平台兜底资产变化
= 0
```

若产品存在外部注资或交割资产转移，必须以独立业务号作为等式中的明确外部项。

## 5. 故障注入

- Asset 超时、成功后响应丢失、重复响应、余额不足。
- 行情消息乱序、重复、断流、未来时间戳和窗口样本不足。
- MySQL 死锁、事务回滚、任务进程在每个资金步骤前后终止。
- Redis 锁超时和重复调度。
- 501 个以上指派候选与并发平仓/撤单。

任何故障都不得通过修改业务号来“修复”；恢复必须证明幂等重放。
