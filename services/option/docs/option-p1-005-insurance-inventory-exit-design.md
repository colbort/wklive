# OPT-P1-005 保险接管库存主动退出设计

## 1. 问题与范围

强平完成后，保险账户会接管客户空头仓位并保存逐笔负 `trade_id` 的保证金 lot。当前系统能够持续计算该库存的数量、标记价值、绝对 Delta、临期和行情失效水位，但没有受控的主动退出入口。

本设计只实现现金结算期权的保险空头库存主动平仓。它不实现自动做市、跨产品 Delta 对冲、实物交割物调整或跨币种换汇；这些能力必须单独审批。首版通过现有公开订单簿提交 `BUY + CLOSE + REDUCE_ONLY + IOC` 限价单，复用成交、资金指令、持仓收益和保证金 lot 释放链路。

## 2. 不变量

1. 只能处理合约配置的 `insurance_user_id/insurance_account_id` 对应的持有中空头仓位。
2. 只能减少库存，不能创建新风险；方向固定为 `BUY`，仓位效果固定为 `CLOSE`，`reduce_only=YES`，订单类型固定为 `IOC`。
3. 数量必须为正、不超过当前可用库存并符合合约 `qty_step`；价格必须为正、符合 `price_tick`，且在新鲜标记价的合约价格带内。
4. 申请人不能复核自己的申请。申请的仓位、数量、限价、理由和证据一经创建不得修改或删除。
5. 批准不等于执行。执行时重新锁定仓位、合约和行情并复核全部经济条件；已暂停、过期、行情陈旧、仓位不足或价格越界时 fail closed。
6. 每个申请只能绑定一个确定性客户端订单键和一个订单 ID。执行响应丢失后重试必须返回原订单，不能重复冻结数量或资金。
7. 订单来源保存为 `ORDER_SOURCE_ADMIN`。普通用户接口不能声明保险退出来源，也不能绕过四眼审批。
8. IOC 未成交或部分成交是合法终态；未成交数量由既有撤单路径释放，已成交数量按现有交易事件更新收益并按 FIFO 释放保险保证金 lot。
9. 退出前保险账户必须有足够可用结算币支付最坏限价权利金和买方费用。首版不允许先解冻接管保证金再赌成交，避免未成交时形成无担保库存。
10. 数据库仅允许 `PENDING_REVIEW -> APPROVED/REJECTED -> SUBMITTED`；历史不可删除、经济字段不可改写、审批人与申请人必须不同。
11. 运行时启用必须同时配置五项正数硬上限：单次数量、单次最坏限价权利金、UTC 日累计数量、相对标记价最大偏离和最小可成交盘口深度。任一缺失、非法或超限均 fail closed；未决申请保守占用 UTC 日预算，直到拒绝或提交。

## 3. 数据模型

新增 `t_option_insurance_inventory_exit`：

| 字段 | 含义 |
| --- | --- |
| `request_no` | 唯一申请号，同时派生确定性客户端订单键 |
| `active_key` | PENDING/APPROVED 时为 `POSITION:<position_id>`，终态为 `REQUEST:<request_no>`；唯一索引阻止同仓并发活动申请 |
| `position_id/contract_id` | 申请创建时锁定的保险库存身份 |
| `insurance_user_id/insurance_account_id` | 合约保险账户快照 |
| `quantity/limit_price` | 不可变退出数量和 IOC 限价 |
| `status` | 1待复核、2已批准、3已拒绝、4已提交 |
| `reason/evidence_ref` | 退出原因和风险/流动性证据 |
| `requested_by/reviewed_by/reviewed_at` | 四眼审批链 |
| `order_id/submitted_by/submitted_at` | 唯一执行结果 |
| `last_error_msg` | 最近一次执行失败原因；不改变批准状态，允许原申请重试 |

`order_id=0` 表示尚未成功提交。执行失败仍保持 `APPROVED`；执行成功后原子写为 `SUBMITTED`。订单的成交/撤销终态从 `t_option_order` 获取，不复制可漂移的成交状态。

## 4. 接口与权限

- `CreateInsuranceInventoryExit`：创建待复核申请。
- `ReviewInsuranceInventoryExit`：独立管理员批准或拒绝。
- `ExecuteInsuranceInventoryExit`：仅执行已批准申请；用保险用户上下文调用管理来源下单逻辑。
- `ListInsuranceInventoryExits`：分页查询申请并返回关联订单当前状态、成交量和未成交量。

Admin API/UI 只在风险运营工作台暴露这些接口。首版执行入口显示不可变数量、限价、订单状态、成交/未成交数量和审批证据；预计最大权利金、可用余额、标记价、价格偏离和库存可用数量由服务端在创建及执行时重新校验，并要求审批证据引用覆盖。生产增强版的实时预览不替代服务端 fail-closed 校验。

## 5. 执行顺序

1. 行锁读取申请，确认 `APPROVED` 且 `order_id=0`。
2. 行锁读取保险仓位；校验合约保险账户、持有状态、可用数量。
3. 读取合约和行情；校验现金结算、`TRADING`、生命周期、日历、标记价新鲜度、合约价格带以及运行时单次/权利金/价格偏离硬限额。
4. 汇总全部未决申请和 UTC 当日已提交申请，验证日累计硬限额；读取限价内可成交卖单并验证最小盘口深度。
5. 使用确定性客户端键提交 `BUY/CLOSE/REDUCE_ONLY/IOC` 管理订单。
6. 既有订单事务冻结退出数量，并创建最坏权利金资金冻结指令。
7. 资金成功后进入既有撮合；IOC 立即成交可用数量并取消剩余数量。
8. 既有交易事件写入 `trade_realized_pnl/fee_paid/total_return`，创建保证金释放指令；Asset 屏障完成后保证金 lot 按 FIFO 收敛。
9. 申请写入唯一 `order_id` 和提交操作人。若第5步成功、第9步响应失败，重试按客户端键找回原订单再补写，不创建第二单。

## 6. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| INS-EXIT-001 | 创建人与复核人相同 | 审批拒绝，0订单、0资金指令 |
| INS-EXIT-002 | 普通客户仓、非保险账户仓或多头仓 | 创建拒绝 |
| INS-EXIT-003 | 数量越界、步长错误、价格 tick 错误、价格带越界 | 创建或执行拒绝，不冻结 |
| INS-EXIT-004 | 批准后仓位减少、合约暂停/到期、行情陈旧 | 执行重新校验并拒绝，申请保持可审计 |
| INS-EXIT-005 | 同一批准申请20路并发执行 | 仅一个 `ORDER_SOURCE_ADMIN` 订单、一次数量冻结和一个客户端键 |
| INS-EXIT-006 | 有1张买方流动性，申请退出2张 | IOC成交1张、撤销1张；保险仓剩1张，冻结数量归零 |
| INS-EXIT-007 | 成交后的资金与持仓 | 买方扣款=卖方净入账+费用；保险交易盈亏、费用、总收益正确；释放保证金等于实际成交数量对应 lot，未成交部分仍有担保 |
| INS-EXIT-008 | 下单成功后写申请结果前模拟响应丢失 | 重试找回原订单，订单/资金/流水均不重复 |
| INS-EXIT-009 | 修改或删除已创建申请，或非法状态回退 | 数据库拒绝 |
| INS-EXIT-010 | 退出后刷新运营指标 | 库存数量、标记价值、Delta 和临期/行情水位按剩余仓位更新；全退后显式为0 |
| INS-EXIT-011 | 开关开启但五项运行时限额任一缺失、为0、非法，或单次上限大于日上限 | 创建、复核和执行均拒绝，0订单、0指令 |
| INS-EXIT-012 | 单次数量/权利金/标记价偏离超过上限，或可成交深度低于下限 | 创建或执行拒绝；等于边界通过；深度检查只计算限价内、非保险账户的活动普通卖单 |
| INS-EXIT-013 | 当日已提交2张且日上限2张，再创建1张；另有跨日前未决申请 | 新申请拒绝且0新增事件；未决申请持续占用预算，已提交只计其 `submitted_at` 所在 UTC 日 |

## 7. 上线前运营资料

仓库可以预填接口、字段、SQL核对项和演练模板；下列资料必须由运营/风控提供真实值并签署：

- 单合约和单标的最大退出数量、单次/单日损失预算、允许价格偏离和最小盘口深度；批准值必须不宽于运行时五项全局硬上限，多合约共用实例时运行时采用最严格值；
- 保险账户可用权利金预算及补资流程；
- 申请、复核、执行角色名单和替班安排；
- 大额退出的市场影响评估、公告/披露要求和禁止交易时段；
- IOC 部分成交、连续无成交、行情失效、余额不足和临近到期的升级路径；
- 生产订单、资金指令、Asset 流水、margin lot、收益分项和 Prometheus 指标证据哈希。

在真实预生产演练、独立风控签字和通知送达记录完成前，本能力保持 `VERIFYING`，不得据此宣称保险库存风险已经完全闭环。

仓库实现与验收证据见 `docs/option-p1-005-insurance-inventory-exit-repository-acceptance.md`。
