# Option 产品运营资料底稿

版本：2026-07-30  
适用范围：现金结算欧式/美式 Option  
状态：运营底稿已完成，合约具体参数、法律文本、联系人和发布时间仍须产品、风控、合规审批

本文用于补齐合约公告、FAQ、到期通知和客服话术的可复用内容。方括号内容是每个合约上线前必须替换的变量，不得直接带占位符发布。

## 1. 当前可对外描述的能力边界

- 支持现金结算 Call/Put。
- 欧式合约在到期时根据最终结算价、用户最新有效指令和自动行权阈值处理。
- 美式现金合约允许在主动行权截止前，对符合条件的多头持仓发起主动行权。
- 到期指令支持 AUTO（按系统规则）、DNE（放弃行权）和相反行权。
- 相反行权只跳过自动行权阈值，不能使价外、零内在价值或扣费后净收益不为正的持仓产生付款。
- 同一持仓的新指令会替代旧指令；历史版本保留。截止时刻及以后不接受新指令。
- 最终结算价来自合约说明书约定的权威行情窗口，经计算、复核、确认后发布；更正使用新版本，不覆盖旧记录。
- 用户可启用紧急交易开关（kill switch），用于立即阻止新单并撤销活动订单；恢复交易需联系客服/运营完成核对后由管理员解除。
- 同一用户不同 `account_id` 之间也执行自成交保护；冲突时取消新进入的 taker 订单。

当前不得承诺：

- 实物交割的 DNE/相反指令和资产不足处置；
- 跨期限、跨标的相关性抵扣或通用 SPAN 组合保证金；
- 未完成 P1-004 历史回测、独立验证和回滚演练的受限组合保证金；
- 未完成 P1-003 预生产验收和审批的 MMP；
- 未完成 COMBO 预生产验收和产品/风控/运营签署的受限组合订单 V1；不得将其描述为支持
  多 maker 扫单、legging、拍卖、跨到期或组合保证金抵扣的完整复杂订单；
- RFQ、大宗；未完成 P2-004 预生产验收的公司行动自动调整；
- 未通过上市检查表和预生产验收的任何产品能力。

## 5. 用户 FAQ

### 5.1 AUTO、DNE 和相反行权分别是什么？

AUTO 使用合约自动行权阈值判断。DNE 明确要求放弃行权。相反行权表示即使未达到自动阈值也请求行权，但仍要求持仓有正内在价值且扣除行权费后净收益为正。

### 5.2 没有提交指令会怎样？

系统按 AUTO 处理。决定使用到期时最新已确认结算价、合约阈值和费用，不使用提交指令时的即时价格。

### 5.3 能否修改指令？

截止前可以提交新版本。新版本生效后旧版本标记为已替代并保留审计记录。截止时刻及以后不能提交新版本。

### 5.4 网络超时后是否需要换一个请求号？

不要立即换号。使用同一客户端请求号重试相同内容，系统会返回原结果；同一请求号提交不同内容会被拒绝。页面查询到的最新有效版本才是到期处理依据。

### 5.5 为什么价内期权没有自动行权？

常见原因包括：每单位内在价值低于自动阈值、扣除行权费后净收益不为正、用户最新指令为 DNE，或持仓在到期前已经关闭。客服应通过审计字段确认原因，不能只按行情截图判断。

### 5.6 为什么相反行权仍未执行？

相反行权不是强制平台进行无经济价值付款。若最终内在价值为零/负数，或扣费后净收益不为正，系统不会行权。

### 5.7 最终结算价为什么不同于到期时看到的价格？

最终结算价按合约约定的来源、时间窗口、样本数量和算法计算，并经过复核；它不一定等于某一时刻的最新成交价。

### 5.8 总收益如何计算？

```text
总收益 = 权利金交易毛盈亏 + 行权/到期结算毛盈亏 - 累计费用
```

历史持仓在分项字段上线前只保存了总额，旧记录可能无法准确拆分到各分项，但总额不会因迁移改变。

### 5.9 DNE 后卖方是否仍需付款？

现金到期结算只按实际行权多头数量分配卖方义务。被 DNE 或阈值规则放弃的多头不获得 payoff，也不会使空头为该数量付款。

### 5.10 当前是否支持实物交割的 DNE？

不支持。实物交割的资产不足、补资和违约处置闭环验收前，不对外开放该能力。

### 5.11 实物交割时资产不足会怎样？

当前实物产品仍未开放。拟采用的安全基线会把多空双方拆成独立配对交割单元：
先收齐双方应交资产并完成对账，再向双方入账。某个用户资产不足只影响其所在单元，
不会让其他健康单元无限等待，也不会由平台先行垫付。

不足资产的单元进入补资期；截止后转违约人工复核。系统不会自动没收已扣资产、
自动放弃行权、拍卖或使用平台资金。具体补资时长、通知、罚则和最终处置必须在产品开放前
写入合约说明并经产品、风控、清算和法务批准。

### 5.12 什么是紧急交易开关（kill switch）？

用户主动启用后，系统拒绝该用户所有新 Option 订单，并撤销仍处于资金冻结、待撮合或
部分成交状态的活动订单。已经完成的成交不会因此被删除。开关保持启用，直到管理员在
核对撤单、冻结资金和用户请求后解除；网络超时时可以重复提交启用请求。

### 5.13 为什么订单返回价格带、持仓上限或自成交保护？

- `ORDER_PRICE_BAND`：委托保护价格超出最新有效标记价允许范围。
- `USER_LONG_LIMIT` / `USER_SHORT_LIMIT` / `OPEN_INTEREST_LIMIT`：包含活动订单和待落仓成交后的投影敞口将超过已发布上限。
- `SELF_TRADE_PREVENTED`：新订单会与同一用户（包括不同 `account_id`）的已有订单成交，系统取消新进入的订单。
- `PRICE_REFERENCE_STALE`：标记价超过新鲜度阈值，系统不会用陈旧价格放行订单。

客服不能建议用户拆分账户、伪造 MMP 报价组或反复提高价格来绕过控制。

### 5.14 异常成交会直接从历史中删除吗？

不会。原订单、成交、持仓事件和 Asset 流水保留用于审计。当前处置方式是在暂停相关合约后，
由一名管理员提出精确平衡的现金更正分录，另一名管理员独立复核；系统先完成所有扣款，
再进行入账。若案件需要改变持仓而不是现金补偿，必须进入专项人工处置，不能用反向下单伪造撤销。

### 5.15 MMP 为什么触发，何时可以重新报价？

MMP 是经平台配置的做市商报价保护，只适用于带报价组的 `POST_ONLY` maker 单。系统在配置
窗口内统计 maker 成交量、成交笔数，以及相对成交前有效标记价的不利成交损失和 maker 手续费；
任一阈值达到即触发并撤销同组报价。普通用户单、非 MMP 单和其他报价组不应受影响。

冷静期结束后的首笔新 MMP 报价可自动恢复窗口；运营也可在核对撤单、资金释放、行情和策略后
带理由人工恢复。若页面显示撤单错误或仍有活动报价，不得承诺恢复时间或要求做市商改组绕过，
应升级风控和 Option/Asset 值班处理。

### 5.16 组合保证金为什么不可用或突然限制？

当前组合保证金只允许同一标的、同一到期日内的欧式期权抵扣，不支持跨期限、跨标的或
通用 SPAN 抵扣。平台必须为结算币配置经过独立审批且处于有效期的参数版本；版本缺失、
尚未生效或风险扫描无法确定使用版本时，系统会拒绝新增组合卖方风险并限制存量账户。

客服应收集租户、UID、结算币、风险账户显示的参数版本和发生时间，升级风控核对版本、
回测/验证证据和风险快照。不得建议用户切换账户、拆分订单或改用旧版本绕过限制，也不得
承诺某一保证金金额；实际金额还取决于持仓、行情、集中度和流动性附加。

### 5.17 为什么后台显示“系列已生成”，合约却还不能交易？

系列复核只证明一批到期时间、行权价、Call/Put 配对和合约参数草稿被原子、可追溯地创建。
所有生成合约都强制处于 `PENDING`，不会因为系列复核自动开放交易。运营仍须逐合约完成交易日历、
行情和做市准备、风险限额、结算配置、公告与上市检查表。

运营不得把“系列已生成”对外表述为“已上市”，也不得直接修改数据库切换状态。若某一生成代码
碰撞或任一参数校验失败，整批应为 0 条；不得人工补插半套 Call/Put。需要修订时创建更高版本、
使用新 request key，并由另一管理员重新复核。

### 5.18 为什么期权链、盘口、成交量或 OI 显示延迟/不一致？

期权链按标的和精确到期时间组织 Call/Put；盘口只统计 Option 已入簿且仍有余量的限价委托，
24小时数据只统计实际成交，OI 只统计已落仓持仓。资金冻结中的订单不会提前进入盘口，
成交到持仓事件完成之间也可能有短暂水位差异。页面应展示生成时间、行情时间和数据质量状态，
不得把标的市场深度称为期权盘口。

若 `oiBalanced=false`、Call/Put 缺腿或数据超过批准时效，标准话术为：
“该期权行情正在进行一致性核对，订单和持仓事实不会因页面展示而修改。请以页面标注的
数据时间为准；恢复后我们将更新状态。” 客服收集合约代码、标的、到期时间、页面生成时间和截图，
升级行情运营与 Option 值班，不承诺具体价格、补造盘口或建议用户据此继续交易。

### 5.19 组合/价差单为什么没有成交，或显示资金处理中？

首版组合单是独立策略簿，只与腿合约、方向和最简比例完全相反的父单成交，不会把普通单腿盘口
自动拼成组合，也不支持拍卖或股票腿。成交必须同时满足父净价和每腿限价。首版 FOK 只检查
价格时间优先的一个最优 maker 是否足量，不会跨多个 maker 汇总；LIMIT 与一个 maker 成交后，
剩余数量继续休眠。

创建后系统按每腿毛额冻结权利金、最大费用和逐仓卖方保证金。全部腿冻结成功前父单显示
`FUNDING` 且0腿入簿；撤销、halt、到期或 kill switch 都按父单一次处理所有腿。一次成交的
所有腿先原子记录；同一 `comboMatchNo` 的全部买方扣冻结成功前不会运行任何腿的持仓事件。
不同合约按各自撮合序号最终落仓，因此成功放款后页面可能短暂显示持仓水位更新时间不同，
但不应出现缺失成交腿或重复资金。

客服应收集 `comboNo`、`clientComboId`、`comboMatchNo`（如有）、父状态、各腿状态和发生时间。
不得建议改单腿、换客户端号重复提交、拆成普通订单、提高某一腿价格绕过净价，或声称首版
提供组合保证金抵扣。

若值班收到 `OptionComboSimpleBookIsolationViolation` 或
`OptionComboDebitBarrierViolation`，标准口径为“系统保护已阻止异常路径，相关交易正在核对”，
不得对外声称已经产生残腿、重复扣款或持仓；必须等订单、Asset 流水、持仓和对账事实确认后再更新。

## 6. 客服排查与标准话术

客服先收集：租户、UID、合约代码、持仓 ID、客户端指令号、页面时间及错误码。不得要求用户提供密码、私钥或验证码。

以下情况必须升级，不得由一线客服自行解释或承诺赔付：

- 同一业务号疑似重复扣款/入账；
- 多头收款与空头扣款总额不一致；
- 已提交指令的内容疑似被原地修改；
- 结算使用未发布版本或窗口外样本；
- 合约级大量用户同时异常；
- 任何拟人工修改数据库状态的请求。

## 7. 运营执行时间线

| 时间 | 责任人 | 动作与证据 |
| --- | --- | --- |
| T-7d | 产品/风控/合规 | 冻结合约说明、阈值、费用、披露；签上市检查表 |
| T-24h | 运营 | 发到期提醒；核对值班人、公告渠道和用户触达结果 |
| T-2h | 技术/清算 | 核对行情三类新鲜度、任务积压、Asset 健康、结算审批人 |
| T-1h | 运营 | 发最后提醒；确认异常账户清单和升级群 |
| 截止时刻 | 技术/运营 | 记录最后接受版本、拒绝计数、服务时间偏差；停止人工口头承诺 |
| 到期后 | 行情/风控/清算 | 计算并双人复核结算价；样本不足则保持等待并告警 |
| 结算中 | 技术/清算 | 监控批次、资金指令、DNE 数量、实际行权量和多空 gross 差额 |

| T+1 | 财务/技术 | 日终复核 PnL 分项、费用、保险/兜底和未关闭问题 |
