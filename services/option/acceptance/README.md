# Option P0 Asset RPC 验收

`run-p0-asset-rpc-e2e.sh` 是仓库级真实 RPC 门禁，不用 mock Asset。脚本在隔离 MySQL 数据库和
独立 Redis 中启动当前工作区的 Asset gRPC，再直接运行 Option 风险扫描及资产指令任务。

## 执行

前置条件：`deploy/docker-compose.yml` 中 MySQL、Etcd 已运行，本机可使用 Docker、Go 和 `nc`。

```sh
services/option/acceptance/run-p0-asset-rpc-e2e.sh
```

脚本只会删除名称匹配 `wklive_option_p0_asset_e2e*` 的隔离数据库、带唯一进程号的临时 Redis
容器和本次创建的 Etcd 键；默认结束即清理。设置 `OPTION_P0_E2E_KEEP=1` 可保留数据库用于
人工取证，但 Redis、Etcd 配置和 Asset 进程仍会关闭。

### Apple Silicon 上的 AMD64 警告

当前 `deploy/docker-compose.yml` 的两个 Beanstalkd 服务使用 `schickling/beanstalkd:latest`；本地
镜像元数据是 `linux/amd64`，而 Apple Silicon 主机是 `arm64`。Docker Desktop 因此显示
“Image may have poor performance, or fail, if run via emulation”：容器会通过指令集模拟运行，
功能验收通常仍可执行，但性能、时延和容量结果不能代表原生或生产环境。该警告不是 Option 业务错误，
也与 `make gen-model` 无关。开发环境可暂时接受；预生产/生产必须改用已固定 digest 的
`linux/arm64` 或多架构 Beanstalkd 镜像，并在切换后重跑消息积压、重连、强杀恢复和容量验收。
不要用显式 `platform: linux/amd64` 隐藏警告，它只会固定启用模拟，并不会消除性能风险。
